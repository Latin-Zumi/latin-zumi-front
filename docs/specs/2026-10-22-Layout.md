# Spec: Layout principal para la billetera

# Fecha
2026-10-24

# Problema
La aplicación necesita una estructura consistente que envuelva las vistas principales (Login, Register, Dashboard) con un header. Además, el panel de administración requiere un layout independiente para no mezclar la navegación pública con la interna.

# Solución propuesta
Implementar un componente Layout que:

Renderice Header y main para todas las rutas públicas.

Use role="main" en el contenedor principal para accesibilidad.

Excluya las rutas que comienzan con /admin, permitiendo que usen su propio AdminLayout.

Mantenga una clase app-layout para aplicar estilos globales.

# Archivos afectados
src/components/layout/Layout.tsx

# Pasos
Definir el componente Layout con prop children.

Usar useLocation para detectar la ruta actual.

Si la ruta comienza con /admin, devolver solo children.

Para el resto, envolver en Header, main con role="main".

Exportar el componente como default.

# Cómo probar
[ ] Renderizar Layout en /login y verificar que muestre Header y main.

[ ] Renderizar Layout en /register y verificar que muestre la estructura completa.

[ ] Renderizar Layout en /dashboard y verificar que muestre la estructura completa.

[ ] Renderizar Layout en /admin y verificar que no muestre Header.

# Riesgos / notas
El layout debe ser flexible para futuras variantes (ej. ocultar footer en páginas de autenticación).

El AdminLayout debe implementarse por separado para mantener la separación de responsabilidades.
