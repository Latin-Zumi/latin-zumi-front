# Spec: Navbar responsive de Latin Zumi

## Fecha
2026-10-26

## Problema
La navegación principal y las acciones de cuenta viven directamente dentro del Header. En pantallas chicas los enlaces se apilan con `flex-wrap` y el encabezado queda desordenado. Además, el Header mezcla marca, navegación y cuenta en un solo componente, lo que lo hace difícil de extender.

## Solución propuesta
Extraer la navegación a un componente `Navbar` que:

- Muestre los enlaces principales con `NavLink`: Inicio, Mi billetera (solo autenticado), Panel admin (solo admin).
- Muestre las acciones de cuenta: Ingresar / Crear cuenta, o nombre del usuario + Salir.
- En móvil (≤ 640px) se colapse detrás de un botón hamburguesa accesible (`aria-expanded`, `aria-controls`).
- Se cierre al navegar a otra ruta y al presionar `Escape`.

El Header queda con el logo + `<Navbar />`.

## Archivos afectados
- src/components/common/Navbar.tsx (nuevo)
- src/components/common/Header.tsx (usa Navbar)
- src/styles/global.css (estilos `.navbar*`)

## Pasos
1. Crear `Navbar.tsx` moviendo la lógica de enlaces y cuenta desde Header.
2. Agregar estado `open` con botón hamburguesa; cerrar al cambiar `pathname` y con `Escape`.
3. Reemplazar en Header la navegación y acciones por `<Navbar />`.
4. Agregar estilos de escritorio (en línea) y móvil (panel desplegable).

## Cómo probar
- [x] Sin usuario → muestra Inicio, Ingresar y Crear cuenta.
- [ ] Con usuario → muestra Mi billetera, nombre y botón Salir.
- [ ] Con admin → muestra Panel admin.
- [x] El enlace de la ruta actual se ve activo.
- [x] En ≤ 640px aparece el botón hamburguesa y abre/cierra el menú.
- [x] Al hacer clic en un enlace o presionar Escape el menú se cierra.
- [x] `npm run build` y `npm run lint` pasan.

## Riesgos / notas
- El Header pasa a ser solo marca + Navbar; los estilos `.site-nav*` y `.site-actions` se reemplazan por `.navbar*`.
- No hay spinner de sesión porque `AuthContext` no expone un estado de carga.
